# Бенто · Ирина: двусторонний Telegram Mini App сервис

Бенто-торты, Москва, м. Водный стадион. Клиент собирает торт в пиксельном конструкторе, заказ мгновенно появляется в пиксельной пекарне Ирины, а статусы и переписка идут в Telegram.

```
client/index.html     Mini App клиента: конструктор торта (GitHub Pages)
admin/index.html      Mini App Ирины: пиксельная CRM с комнатами, drag-and-drop, WebSocket (GitHub Pages)
shared/common.js      меню, цены, настройки кондитерской (apiUrl!) и формирование заказа
server/main.py        FastAPI + aiogram 3 + SQLite: REST, WebSocket, два бота
server/requirements.txt, server/.env.example
```

**Как это работает.** Клиент жмёт «🎂 Собрать торт» в клиентском боте и отправляет заказ на `POST /api/orders` (подпись Telegram `initData` проверяется на сервере). Сервер сохраняет заказ, шлёт Ирине push в служебный бот и событие по WebSocket в её кабинет: у двери появляется человечек, звенит колокольчик. Перетаскивание гостя между комнатами меняет статус заказа и шлёт клиенту сообщение в его бот. Ответы Ирины из вкладки «Диалог Telegram» уходят клиенту через клиентского бота, а ответы клиента появляются в кабинете.

## 1. Боты

1. В [@BotFather](https://t.me/BotFather) создайте двух ботов командой `/newbot`: клиентского и служебного. Сохраните оба токена.
2. Узнайте Telegram ID Ирины и сотрудников: напишите служебному боту `/start` после запуска сервера, он ответит вашим ID (для не-сотрудников).

## 2. GitHub Pages (фронтенд)

1. Создайте репозиторий на GitHub и загрузите в корень содержимое этого архива (папки `client`, `admin`, `shared`, `server`, файл `README.md`). Файл `.env` в репозиторий не кладите.
2. Settings → Pages → Source: *Deploy from a branch* → ветка `main`, папка `/ (root)`.
3. Через минуту страницы будут доступны:
   - клиент: `https://<логин>.github.io/<репозиторий>/client/`
   - кабинет: `https://<логин>.github.io/<репозиторий>/admin/`

   Папка `shared` должна лежать рядом с `client` и `admin`: страницы подключают `../shared/common.js`.

## 3. Сервер (бэкенд)

Нужен Python 3.10+ и публичный **HTTPS**-адрес (Telegram не открывает Mini App с http, а страницы на https не могут обращаться к http API).

```bash
cd server
cp .env.example .env          # впишите токены и адреса (см. ниже)
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py                # сервер на порту 8000, оба бота запускаются вместе с ним
```

Файл `server/.env`:

| Переменная | Что вписать |
|---|---|
| `CLIENT_BOT_TOKEN` | токен клиентского бота |
| `ADMIN_BOT_TOKEN` | токен служебного бота |
| `ADMIN_IDS` | Telegram ID сотрудников через запятую |
| `CLIENT_URL` | `https://<логин>.github.io/<репозиторий>/client/` |
| `ADMIN_URL` | `https://<логин>.github.io/<репозиторий>/admin/` |
| `ALLOWED_ORIGINS` | `https://<логин>.github.io` (без пути) |
| `PORT`, `DB_PATH` | порт и файл базы (по умолчанию 8000 и `bento.db`) |

**HTTPS для API.** Самый простой вариант на VPS: [Caddy](https://caddyserver.com) сам выпустит сертификат. В `/etc/caddy/Caddyfile`:

```
api.ваш-домен.ru {
    reverse_proxy localhost:8000
}
```

Для быстрой проверки без домена: `cloudflared tunnel --url http://localhost:8000` выдаст временный https-адрес.

Чтобы сервер работал постоянно, запустите его как systemd-сервис или в `tmux`/`screen`.

## 4. Связать фронтенд с сервером

В файле `shared/common.js` замените `apiUrl` на публичный HTTPS-адрес сервера (например `https://api.ваш-домен.ru`), закоммитьте и подождите, пока Pages обновится. Перезапустите `python main.py` после правки `.env`.

## 5. Проверка

1. Откройте клиентского бота, нажмите `/start` → «🎂 Собрать торт» → соберите торт → «Заказать».
2. Служебный бот пришлёт Ирине уведомление; по кнопке «🏪 Войти в пекарню» откроется кабинет: у двери появится новый гость.
3. Перетащите гостя на кухню: клиент получит в боте сообщение «Заказ на кухне». Откройте чек, вкладку «💬 Диалог Telegram», отправьте ответ: он придёт клиенту.
4. Кнопка «➕ Симулировать входящий заказ» создаёт тестовый заказ через тот же сервер, без сообщений клиенту.

**Локальная отладка без Telegram:** поставьте `DEV_MODE=1` в `.env`, запустите сервер и откройте `client/index.html` и `admin/index.html` из локального веб-сервера (`python -m http.server` в корне проекта). Проверка подписи при этом отключена: на боевом сервере держите `DEV_MODE=0`.

## API

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| POST | `/api/orders` | клиент | создать заказ (заголовок `X-Init-Data`) |
| GET | `/api/admin/orders` | кабинет | активные заказы с перепиской |
| PATCH | `/api/admin/orders/{id}` | кабинет | сменить статус: `new`, `accepted`, `work`, `ready`, `done` |
| POST | `/api/admin/orders/{id}/reply` | кабинет | ответить клиенту через бота |
| POST | `/api/admin/simulate` | кабинет | тестовый заказ |
| WS | `/ws?init_data=...` | кабинет | события `order_new`, `order_update`, `chat` |
| GET | `/health` | любой | проверка работы |

## Что важно знать

- Цены в «от» ориентировочные: окончательную сумму с учётом сложности дизайна Ирина согласует в чате. Меню и цены лежат в `shared/common.js`.
- Уровень, монеты, склад и квесты пока хранятся в браузере устройства Ирины (`localStorage`), заказы и переписка на сервере.
- Резервная копия: файл `server/bento.db` (SQLite) достаточно копировать раз в день.
